# Climatological Post-Processing Metrics Documentation

This document describes the methodologies, thresholds, and computation strategies used for the metrics generated by the post-processing pipeline. It explains exactly what is computed in the code, how it is implemented, and how to interpret the resulting figures.

The metrics are divided into two main categories: **Mean State Metrics** and **Extreme Events Metrics**.

---

## 1. Mean State Metrics

### 1.1 Mean Error (Bias)
- **What it computes:** The systematic difference between the model's precipitation and the reference (MSWEP) precipitation.
- **What we implemented:** 
  We compute the mean precipitation for the model and the reference over the evaluation period (e.g., Annual, DJF). The Bias is then calculated as `Bias = Model Mean - Reference Mean`. 
  - `strategy = mean_first`: The temporal mean is calculated first for each dataset, and then the difference is taken.
  - `strategy = daily_first`: The difference is calculated daily, and then averaged over time.
- **How to interpret:**
  - **Values > 0 (Red/Orange):** The model overestimates precipitation compared to the reference (Wet Bias).
  - **Values < 0 (Blue):** The model underestimates precipitation compared to the reference (Dry Bias).
  - **Values ≈ 0 (White):** The model perfectly matches the reference. 
  - *Spatial Maps* show where the model struggles. *Temporal Evolutions* show if the bias drift changes over the years.

### 1.2 Root Mean Square Error (RMSE)
- **What it computes:** The standard deviation of the residuals (prediction errors), indicating the absolute fit of the model to the reference data.
- **What we implemented:** 
  For each day, the squared difference between the model and reference `(Model - Ref)^2` is computed. These squared differences are averaged over the period (e.g., year or season), and finally, the square root is taken.
- **How to interpret:**
  - RMSE is always non-negative (`>= 0`). 
  - **Lower values (Light colors):** Indicate better agreement and less error between the model and the observation.
  - **Higher values (Dark colors):** Indicate large discrepancies. Since it squares errors before averaging, RMSE heavily penalizes days with very large errors (e.g., missing an extreme storm).

### 1.3 Pearson Correlation (Correlation)
- **What it computes:** The linear correlation coefficient between the model and reference precipitation, measuring temporal phase alignment (does the model rain on the same days it actually rained?).
- **What we implemented:**
  Using `xskillscore.pearson_r`, we calculate the correlation across the time dimension for each pixel. We strictly compute the **Anomaly Correlation**. The code forces `use_anomaly=True`, which subtracts the mean state before computing the correlation to isolate the model's ability to predict variability rather than just following the standard seasonal cycle.
  - **Current Configuration:** The active config uses `strategy = per_year`. This means for every year independently, the code subtracts the *mean of that specific year* from the daily values to compute the anomalies, and then correlates these daily anomalies. The yearly correlations are then averaged to produce the final map.
- **How to interpret:**
  - **Values close to 1 (Green):** Perfect positive correlation. The model accurately captures the timing of precipitation events.
  - **Values close to 0 (Yellow/White):** No correlation. The model's rain events are random relative to observations.
  - **Values < 0 (Red):** Negative correlation (rare for precipitation).

## 2. Extreme Events Metrics

### 2.1 Consecutive Dry Days (CDD)
- **What it computes:** The maximum length of a dry spell in a given period.
- **What we implemented:** 
  A dry day is strictly defined as having precipitation `< 1.0 mm/day`. For each year, we compute a boolean array of dry days. We then find the maximum number of consecutive `True` values (consecutive dry days). This is done for models and MSWEP independently.
- **How to interpret:**
  - **CDD values (Days):** Represents the longest drought period in that year/season. 
  - **CDD Error (Model - MSWEP):** 
    - Positive error means the model produces excessively long dry spells compared to reality.
    - Negative error means the model rains too frequently (the "drizzle effect"), preventing long dry spells from forming.

### 2.2 Wet Days Frequency (R01)
- **What it computes:** The percentage of days that are classified as "wet".
- **What we implemented:** 
  We create a binary mask where precipitation `>= 1.0 mm/day` is `True` (1), and `< 1.0` is `False` (0). We calculate the temporal mean of this mask and multiply by 100 to get a percentage. Computed independently for all datasets.
- **How to interpret:**
  - **Higher R01:** Means the region experiences frequent rain events.
  - **R01 Error (Model - MSWEP):**
    - Positive error: The model rains too often (common in global models exhibiting the "drizzle problem").
    - Negative error: The model misses smaller rain events, producing too few wet days.

### 2.3 Heavy and Extreme Precipitation Amount (R95 / R99)
- **What it computes:** The mean precipitation intensity on extremely wet days.
- **What we implemented:**
  1. We identify the 95th (or 99th) percentile threshold of daily precipitation using **only the wet days** (`>= 1.0 mm/day`) from the **reference dataset (MSWEP)** over the entire period.
  2. We apply this exact same reference threshold to all models.
  3. We calculate the mean precipitation amount for days where the model precipitation exceeds this threshold.
- **How to interpret:**
  - Shows how intense the most severe storms are.
  - **R95/R99 Error:** 
    - Negative error: The model's extreme storms are too weak compared to reality.
    - Positive error: The model overestimates the intensity of extreme storms.

### 2.4 Heavy and Extreme Precipitation Frequency (R95_Freq / R99_Freq)
- **What it computes:** The number of days per year where precipitation exceeds the extreme percentiles.
- **What we implemented:**
  Using the exact same 95th (or 99th) percentile threshold derived from the **reference dataset (MSWEP)** wet days, we count the number of days per year where each model's precipitation is greater than or equal to this threshold.
- **How to interpret:**
  - **Values (Days):** The average number of extreme rainfall events per year/season.
  - **Frequency Error:**
    - Positive error: The model generates too many extreme events.
    - Negative error: The model fails to trigger extreme events frequently enough.

### 2.5 Relative Operating Characteristic Skill Score (ROCSS)
- **What it computes:** The model's skill in discriminating between rain events and non-rain events compared to random guessing.
- **What we implemented:** 
  The reference data is binarized (`1` for `>= 1.0 mm/day`, `0` otherwise). The model's continuous precipitation predictions are used as probability/scores to predict the binary observation. We calculate the Area Under the Curve (AUC) and convert it to ROCSS = `2 * AUC - 1`.
- **How to interpret:**
  - **ROCSS = 1.0:** Perfect discrimination (the model perfectly separates wet from dry days).
  - **ROCSS = 0.0:** No skill (equivalent to random guessing).
  - **ROCSS < 0.0:** Worse than random guessing.
  - *Note:* This metric strictly evaluates the model's ability to trigger rain when it should, ignoring the actual *amount* of rain produced.

### 2.6 Q-Q Plot (Quantile-Quantile Distribution)
- **What it computes:** Compares the full distribution shape of precipitation intensities between the models and the reference.
- **What we implemented:**
  We flatten the spatial and temporal dimensions of the datasets. We filter out all dry days (`< 1.0 mm/day` default). We compute exactly 100 quantiles (from 1st to 100th percentile) for the observations and each model, and plot them against each other.
  *Note:* Just like the other metrics, QQ-plots are now computed iteratively over all geographical subregions (e.g., `north`, `south`) and for all specific seasons (`Annual`, `DJF`, `MAM`, `JJA`, `SON`), allowing you to analyze distribution integrity temporally and spatially.
- **How to interpret:**
  - **The 1:1 Line (Black dashed):** Represents perfect agreement between model distribution and observation distribution.
  - **Lines below 1:1:** The model underestimates the intensity of events at those quantiles (usually happens at the right tail for extreme events).
  - **Lines above 1:1:** The model overestimates precipitation intensity.
  - This plot is crucial for checking the *physical integrity* of the model's distribution, irrespective of spatial or temporal errors.

## General Note on Output Figures
For most metrics, the pipeline outputs four standard figures per period (Annual, DJF, etc.):
1. **Spatial Maps (`*_spatial_map_*.png`):** Shows the climatological mean of the metric across the map for all models and the reference. Maps automatically zoom to the bounding box of the selected subregion.
2. **Spatial Error Maps (`*_spatial_error_*.png`):** Shows the spatial distribution of the difference (`Model - Reference`). This highlights *where* the model fails geographically.
3. **Temporal Evolution (`*_evolution_*.png`):** Plots the domain-averaged metric over time. Useful for spotting temporal trends, interannual variability, and checking if models drift or fail in specific years.
4. **Distribution Boxplots (`*_boxplot_*.png`):** Shows the spread, median, and interquartile range of the metric across all pixels and years. The red diamond (`♦`) marks the spatial-temporal mean. Useful for comparing the overall distribution of values across models.

All outputs (data `.nc`/`.csv` and `.png` figures) are seamlessly organized into dedicated subdirectories following this strict hierarchy to prevent overwriting:
`results/<experiment_name>/<start_date_end_date>/<region_name>/test/<metric_name>/`
